      How to get a browser token for IDM or VCF Operations
      1. Open the system in Edge or Chrome and sign in.
      2. Press F12, then open the Network tab.
      3. In the page, click something (open a list) so requests show up.
      4. Right-click any request to that host, choose Copy, then Copy as fetch.

    3. 2

      Connect to VCFA

      VCFA needs a token. Choose how you want to sign in, then test the connection.

      Sign in with
      How to get the browser token from the browser
      1. Open the VCFA organization in Edge or Chrome and sign in.
      2. Press F12 to open the developer tools, then open the Network tab.
      3. In the VCFA page, click something (open the organizations list). Requests appear in the list.
      4. Type cloudapi in the filter box of the Network tab.
      5. Right-click any request, choose Copy, then Copy as fetch. Copy as cURL also works.
      6. Click the token box above and paste with Ctrl+V. The whole text is fine here. The page takes out the token and shows Token found.

      Without copying the whole request: click one request, open the Headers tab, find authorization under Request Headers, and copy only the long text after Bearer .

      A browser token expires within minutes. If a step says the login failed, copy a new one and run the step again.
      How to get an API token

      Create an API token in the VCFA interface, copy it once, and paste it into the box above. Choose API token in the list before you test. An API token does not expire within minutes, so it suits longer sessions. Delete it in VCFA when you are done.

    5. 4

      Create the groups and users in VCFA

      Creates what the dry run listed. Existing groups and users are not recreated, and missing roles are added. Roles are never removed. Group membership is not copied: VCFA takes it from the identity provider at each login.

      The scope or import file changed since your last dry run. Run the dry run again before you create anything.
